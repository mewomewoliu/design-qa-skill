What failed, why, and what to do

P1

F01 Offline snoozes look confirmed when they're only queued

Design gapObserved in demo Affects S02

Expected

A clear 'saved on phone, will send when online' state that persists until sync.

Actual

Same success toast and list state as online; spec doesn't mention offline.

Why it matters. Technician leaves believing the supervisor sees it; supervisor plans around stale data. Frequency unknown, but no-signal rooms are common (E04).

Fix

Add an offline variant of the toast and a pending marker on the task until sync; reuse the app's existing offline banner.

Retest. S02: snooze offline → see pending marker → reconnect → marker clears and supervisor view updates.

P1

F02 Supervisors lose the reason and history of snoozes

Design gapStatic evidence Affects S03, S06

Expected

Supervisors can see why a task moved and whether it keeps moving.

Actual

Reason is optional and device-local; each snooze overwrites the last.

Why it matters. Snooze can hide exactly the stale work the feature was meant to surface (intent: problem).

Decision needed

Decide how much reason capture to require before build. Recommend B if supervisors confirm they plan from reasons.

OptionTrade-off
A — Optional free-text reason, sharedLowest friction; reasons often blank.
B — Required quick reason chips (No parts / No access / Other)One extra tap; structured, reportable.
C — No reason; show snooze count and history onlyZero friction; supervisor sees pattern but not cause.

Retest. S03 and S06 with the chosen option.

P3

F03 Spanish snooze label truncates

Design gapObserved in demo Affects S05

Expected

Full label readable, or a shorter translation.

Actual

Fixed-width button cuts the label.

Why it matters. Minor, but hides which time is being chosen.

Fix

Let the button wrap to two lines or use the shorter string 'Posponer a mañana'.

Retest. S05 in Spanish at default and large text size.

Passed in both layers: S01, S04.

Intent & evidence

Can't finish on site → snooze with a reason → task reappears when it can be done → supervisor plans around it → fewer stale overdue tasks

Source
plan/snooze-task/intent.md captured
Problem
Technicians can't finish some tasks on the day (no parts, no access) and the task stays overdue, hiding real problems.
Users
Field technicians (primary); supervisors who plan the next day (secondary).
Job to be done
Move a task I can't do today to a sensible later time, without losing why.
Success
  • Task moves to the chosen time and leaves today's overdue list
  • Supervisor can see that it was snoozed and why
Out of scope
  • Recurring task rules
  • Desktop planning view
